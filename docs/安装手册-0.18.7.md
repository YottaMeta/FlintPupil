# 燧瞳社区版 · 安装与运维手册

> 适用版本：0.18.7（社区版交付包；0.16.0 及以后通用）
> 更新日期：2026-11-22
> 社区版：单节点、永久免费、整套自部署、无任何厂商服务（无在线验活、无信标、无自动更新）。

## 1. 交付包内容

```
FlintPupil-community-<version>-linux-amd64/
├── install.sh            离线安装脚本
├── uninstall.sh          停止 / 卸载脚本
├── VERSION               版本号
├── MANIFEST.sha256       全部文件校验和
├── images/
│   └── flintpupil-images.tar   api（community）+ postgres + nginx 三个镜像
├── app/
│   ├── docker-compose.yml
│   ├── nginx.conf        前端静态 + /api + WebSocket 反代
│   ├── web/              社区版前端
│   ├── geoip/            离线 GeoIP 索引（约 130MB）
│   └── releases/         已签名 agent 二进制（供一键安装接口分发）
```

交付包为完整离线包：安装过程不拉取任何外网镜像，也不访问厂商服务。
安装手册**单独发送**（不在包内），随交付物一起提供。

## 2. 环境要求

| 项 | 要求 |
| --- | --- |
| 架构 | linux/amd64（x86_64） |
| 操作系统 | 主流 Linux（Rocky / CentOS / Ubuntu / Debian / openEuler） |
| 容器 | Docker Engine 24+，Docker Compose v2 插件（`docker compose version` 可用） |
| 内存 | 建议 4GB（最低 2GB；低于 2GB 时大数据量下查询会变慢） |
| CPU | 建议 2 核 |
| 磁盘 | 建议 20GB 起（事件明细按天增长，社区版默认保留 7 天） |
| 端口 | 默认 80；如被占用可用 `--port` 更换 |
| 系统时间 | 必须开启 NTP 同步（TOTP 与事件时间依赖系统时钟） |

### 2.1 安装 Docker（未安装时）

交付包**不包含 Docker**，需要先在目标机安装 Docker Engine 与 Compose v2 插件。

Rocky / CentOS Stream 8+ / 9：

```bash
sudo dnf install -y dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
```

CentOS 7（已 EOL，仍可用 yum 安装）：

```bash
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
```

> CentOS 7 的官方镜像源可能已不可用。若 `yum` 安装失败：在一台**同架构**的联网机器下载 `containerd.io`、`docker-ce`、`docker-ce-cli`、`docker-compose-plugin` 的 rpm，拷到目标机执行：
>
> ```bash
> sudo yum localinstall -y ./*.rpm
> sudo systemctl enable --now docker
> ```

Ubuntu / Debian：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
```

完全离线机器：用同架构联网机下载上述 rpm/deb（Docker 官方仓库 `Packages` 目录），拷到目标机 `rpm -ivh` / `dpkg -i` 安装，然后 `systemctl enable --now docker`。

安装后确认：

```bash
docker --version
docker compose version
```

预期：Docker 24+，Docker Compose version v2.x。

安装前检查：

```bash
docker --version
docker compose version
free -m
df -h /opt
ss -ltn | grep ':80 '
```

## 3. 安装

### 3.1 解压与校验

```bash
tar -xzf FlintPupil-community-<version>-linux-amd64.tar.gz
cd FlintPupil-community-<version>-linux-amd64
sha256sum -c MANIFEST.sha256        # 全部 OK 再继续
```

如同时提供了外层 `.tar.gz.sha256`，可先核对整包：

```bash
sha256sum -c FlintPupil-community-<version>-linux-amd64.tar.gz.sha256
```

### 3.2 执行安装

```bash
sudo ./install.sh
```

可选参数：

```bash
sudo ./install.sh \
  --dir /opt/flintpupil \        # 安装目录（默认）
  --port 80 \                    # HTTP 端口
  --project flintpupil \         # Compose 项目名（默认；同机多套部署时区分）
  --public-url http://10.0.0.5 \ # 对外地址，用于生成节点接入命令
  --admin admin \                # 管理员用户名
  --no-totp                      # 关闭动态验证码（不推荐）
```

`--public-url` 必须是**被监控主机能访问到服务端的地址**（公网 IP / 内网 IP / 域名，含端口）。不填时脚本按本机首个 IP 自动推导，多网卡或 NAT 环境请显式指定。

安装脚本会依次完成：

1. 校验交付包完整性；
2. 检查 Docker / Compose / 端口 / 内存；
3. 复制程序到安装目录，生成 `.env`（随机数据库口令，600）；
4. `docker load` 三个镜像并启动 `db / api / web`；
5. 等待健康检查，确认 `edition=community`；
6. 创建管理员，把账号与 TOTP 密钥写入 `<安装目录>/admin.txt`（600）。

成功后输出访问地址与管理员文件路径。

### 3.3 首次登录

```bash
sudo cat /opt/flintpupil/admin.txt
```

文件包含 `username / password / totp_secret / otpauth` 四行。用验证器（Google Authenticator / Microsoft Authenticator / 1Password 等）扫描或手动录入 `otpauth`，浏览器打开访问地址登录。

> 该文件只出现一次，口令无法从数据库恢复。请立即转存到密码管理器，并删除或妥善保管该文件。

### 动态验证码（TOTP）：用手机绑定（不用扫码）

安装时默认启用动态验证码，密钥在 `<安装目录>/admin.txt` 的 `totp_secret` 行。**不需要二维码，手动把密钥粘进 App 即可。**

#### 1. 在服务器上取密钥

```bash
sudo grep '^totp_secret:' /opt/flintpupil/admin.txt
```

输出类似：

```
totp_secret: JBSWY3DPEHPK3PXP
```

复制**冒号后面的整串**（不含空格）。这就是要粘进手机的密钥。

#### 2. 手机安装验证器

- iPhone：App Store 搜索 “Microsoft Authenticator” 安装；
- Android：应用商店搜索 “Microsoft Authenticator” 安装；
- Google Authenticator 也可以，步骤类似。

#### 3. 手动添加（以 Microsoft Authenticator 为例）

1. 点右下角的 **“+”**；
2. 选择 **“Enter manually”**（手动输入，不要扫码）；
3. **Account name** 输入：`燧瞳`；
4. **Private key / Secret key**：粘贴第 1 步复制的字符串；
5. 点 **“Add”** 完成。

列表中会出现「燧瞳」，并显示每 30 秒变化的 6 位数字。

Google Authenticator：右下角 **“+”** → **“输入设置密钥”** → 填名称和密钥 → **“添加”**。

#### 4. 登录

浏览器输入用户名、密码，再输入 App 里当前的 **6 位动态码**。

提示“验证码错误”时：先确认手机时间设置为“自动同步”，动态码每 30 秒变化，取当前那一个。

#### 5. 不想用手机 / 没有智能手机

- 安装时加 `--no-totp`，登录只用密码（不推荐）；
- 已安装的可以关闭：`reset-totp --username admin --disable`；
- 也可以用电脑端 1Password / Bitwarden 等支持 TOTP 的工具，手动录入同一密钥。

#### 6. 密钥丢失或轮换

```bash
cd /opt/flintpupil
sudo docker compose exec -T api python -m app.cli reset-totp --username admin </dev/null > /root/totp-new.txt
sudo chmod 600 /root/totp-new.txt
```

新密钥在 `/root/totp-new.txt`，按上面步骤重新绑定；旧验证器立即失效。


## 4. 接入被监控节点

1. 登录控制台 →「节点管理」→「接入新节点」；
2. 填写节点名称，生成一条安装命令（内置一次性令牌，默认 15 分钟有效）；
3. 在被监控主机以 root 执行该命令：
   ```bash
   curl -fsSL http://<服务端地址>/api/v1/install.sh | sudo bash -s -- \
     --server http://<服务端地址> --token <一次性令牌> --name <节点名>
   ```
4. 节点卡片出现后 30 秒内应显示在线、序号持续增长、0 缺口。

说明：

- 社区版**最多接入 1 个节点**，第 2 个新主机会被拒绝并提示升级专业版；同一台主机重装不占新配额（同指纹重绑）。
- 安装脚本会装 systemd 单元 `hostmetrics`、auditd 规则（可 `--no-auditd` 跳过）与配置锁；重复执行即升级。
- 被控端只需**出站**访问服务端 HTTP 端口，不需要开放入站。

## 5. 目录与数据

```
/opt/flintpupil/
├── .env                运行配置（数据库口令、对外地址、端口），600
├── admin.txt           管理员凭据，600（首次安装生成）
├── docker-compose.yml
├── nginx.conf
├── web/                前端静态文件
├── geoip/              离线地理索引（只读挂载）
├── releases/           agent 签名产物（只读挂载）
└── data/postgres/      PostgreSQL 数据目录（唯一需要备份的目录）
```

三个容器：`db`（PostgreSQL，不对外）、`api`（FastAPI，不对外）、`web`（Nginx，对外仅暴露 `FP_HTTP_PORT`）。

## 6. 日常运维

```bash
cd /opt/flintpupil
docker compose ps                     # 状态
docker compose logs -f api            # API 日志
docker compose logs -f web            # 访问日志
docker compose restart api            # 重启 API
docker compose up -d                  # 应用配置变更
```

健康检查：

```bash
curl -fsS http://127.0.0.1/api/healthz
# {"status":"ok","version":"0.18.7","edition":"community"}
```

### 6.1 备份

只需备份 `data/postgres`，推荐 `pg_dump`：

```bash
cd /opt/flintpupil
docker compose exec -T db pg_dump -U flintpupil -d flintpupil -Fc > /root/flintpupil-$(date +%F).dump
```

恢复（停机后）：

```bash
cd /opt/flintpupil
docker compose stop api
docker compose exec -T db pg_restore -U flintpupil -d flintpupil --clean --if-exists < /root/flintpupil-2026-11-17.dump
docker compose start api
```

建议加每日 cron，并把 dump 复制到异机。`.env` 与 `admin.txt` 也要单独备份（含数据库口令与管理员凭据，注意权限）。

### 6.2 事件保留期

社区版默认保留 **7 天**。可在 `.env` 中调整后 `docker compose up -d`：

```
FP_EVENT_RETENTION_DAYS=14
```

### 6.3 事件护栏

每节点默认日配额 50 万条入库明细、瞬时 3,000 EPS；达到 80% 产生告警，达到 100% 后噪声明细不再入库（高危事件始终保留）。可在 `.env` 中调整（0 表示不限制）：

```
FP_EVENT_DAILY_LIMIT=500000
FP_EVENT_EPS_LIMIT=3000
FP_EVENT_WARN_RATIO=0.8
```

控制台「设置 → 事件护栏」可查看当日用量。

## 7. 升级

1. 获取新版本交付包并校验；
2. 解压后执行：
   ```bash
   sudo ./install.sh --upgrade
   ```
   脚本会覆盖程序文件、导入新镜像并重启，**保留** `.env`、数据库与管理员凭据。
3. 升级后确认 `curl -fsS http://127.0.0.1/api/healthz` 的版本号。

跨大版本升级前请先做一次数据库 dump。

## 8. 卸载

```bash
sudo ./uninstall.sh              # 停止容器，保留数据
sudo ./uninstall.sh --purge      # 二次确认（输入 yes）后删除整个安装目录
sudo ./uninstall.sh --purge --images   # 同时删除本地镜像
```

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `端口 80 已被占用` | 用 `--port 8080` 换端口；或先停掉占用进程 |
| 数据库反复重启 / `could not write ... Operation not permitted` | 老内核（如 CentOS 7）+ 新版 Docker 的 seccomp 限制；0.18.0 包已在 db 服务加入 `security_opt: [seccomp:unconfined]`，使用该包或给 db 手动加该项 |
| `未找到 docker compose 插件` | 安装 Docker Compose v2 插件（`docker-compose-plugin` 包） |
| 登录提示动态验证码错误 | 服务器时间未同步；`timedatectl` 检查 NTP，校准后用当前验证码重试 |
| 页面能开但登录后空白 | 浏览器缓存了旧入口；强刷（Ctrl+F5） |
| 节点一直离线 | 被控端出站访问不到 `--public-url`；在节点上 `curl <服务端地址>/api/healthz` 验证 |
| 来源地理全是「未知来源」 | `geoip/` 未挂载或索引缺失；`docker compose logs api | grep -i geoip` 检查 |
| 接入第 2 个节点被拒 | 社区版单节点上限；升级专业版后按 License 配额接入 |
| 访问 `/wall`、`/globe` 返回 404 | 社区版不包含该能力，属预期 |
| 磁盘持续增长 | 事件明细按天增长，默认保留 7 天；可缩短 `FP_EVENT_RETENTION_DAYS` 或提高采样降噪 |

## 10. 安全建议

- 不要把 `data/` 或 `.env` 暴露到 Web 目录；两者权限保持 600/700。
- 若需公网访问，建议前置 HTTPS：在 80 端口前再加一层带证书的反代（或云负载均衡），并在 `.env` 增加 `FP_COOKIE_SECURE=1`。
- 定期轮换管理员口令（容器内执行 `python -m app.cli reset-password --username admin`），并吊销旧会话。
- 节点接入令牌一次性、15 分钟有效；不要手工转贴到不相关主机。
- 备份文件含数据库口令与管理员凭据，异地保存时应加密。

## 11. 与专业版的差异与升级路径

社区版保留：登录、总览、事件检索、攻击者画像（基础）、节点管理与接入、基础采集、基础告警、采集目标、事件护栏。

专业版额外提供：3D 全球溯源、指挥大屏 `/wall`、MCP 接入、告警外送（IM/Webhook/邮件）与确认静默、变更溯源与按秒时间线、文件完整性、入侵检测增强、配置版本灰度回滚、签名自动更新、License 管理与事件 CSV 导出。

升级方式：获取专业版交付包，用新版 `install.sh` 覆盖安装并导入 License（指纹绑定）；core 数据兼容，专业版会补建所需表，**不支持从专业版降级回社区版**。
